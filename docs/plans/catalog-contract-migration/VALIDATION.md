## 本仓检查

已有门禁继续保留：npm run validate、npm test、npm run sources:gaps:check、git diff --check；新增按V2合同检查字段消费/依赖矩阵、模型绑定覆盖、来源字段、显式override理由、生命周期、计价单位、退役活跃引用和生成投影diff。

P0完成时只读扫描不应影响主数据；P1客户端按改动范围测试和构建，不把全库typecheck默认作为本地门禁；CI按项目规则执行。真实调用使用已有授权的测试账号，保存不含凭据的最小请求/状态/费用摘要，不能把模拟或schema校验称为接口实测。

## 分批发布

1. 客户端PR：门控+schema/resolver+迁移+退役执行机制，发布实际V_contract并验证安装包有效版本。
2. config-center基础格式/生成工具PR：发布V2目录与兼容投影选择契约，校验所有未知字段/旧客户端路径；不提前删除旧required字段。
3. 按供应商迁移数据PR：优先已证据充分的思考、预算、cache/speech字段；每批更新source文档和派生清单。缺证项留独立队列。
4. 已确认退役Provider/域名PR：精确scope、用户状态和默认回退一起验证。产品下架与厂家停服日期分别写明。
5. 完成铺开后退出V1手工作者字段与兼容读取；冻结/归档旧投影有明确时间、覆盖率与回滚边界，不只因为代码已合并就移除。

每个数据批次基于当时最新远端manifest递增版本。required checks全绿、CLEAN/MERGEABLE、精确head和零未解决review后合并；随后复核远端数据/编译产物和main CI。文档PLAN本身不递增presetDataVersion。

## 回滚约束

保留上一份canonical与两种编译产物；数据回退仍用更高presetDataVersion发布，不能降版本号让客户端不拾取。客户端迁移回滚保护用户覆写与凭据；不恢复已证实停服域名、错误身份或无效协议。跨格式不可安全降级时保留最后有效格式并要求支持的客户端，不强塞旧schema。

## 执行报告

报告真实迁移字段数、仍未分类/待核字段、接入覆盖/匹配层级、解决/保留的差异、已下架具体host/path/provider范围、支持最低版本与未支持旧二进制边界、账号/协议实测结果和剩余依赖。完成率不能只按来源指纹或新增文件数量计。
